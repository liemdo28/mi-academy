## Investigated and kept — not true duplicates or too risky to remove unreviewed

| Path | Why kept |
|---|---|
| `packages/game_core` (Python) | Real ~21-file game-engine module (`GameRegistry`, `GameEngineBase`, math_race engine). Not imported by `apps/api` (which reimplements its own game logic in `routes/games.py`), but **is** used by `tools/mi_cli/mi.py` and has its own passing test suite (`packages/game_core/tests`, run in CI). Whether `apps/api/routes/games.py` should be migrated onto this engine instead of its own logic needs a deeper design review than this session's scope — flagged in `NEXT_PHASE_PLAN.md` rather than acted on blind. |
| `contracts/shared_contracts.py` (top-level, Python) | A third independent definition of `MiGameResult`/`MiGameLaunchRequest`/etc., as a dataclass registry. Zero imports from `apps/api`, but **is** loaded by `tools/mi_cli/mi.py`'s `test-contracts`/`audit` commands (`from shared_contracts import CONTRACT_REGISTRY`). Deleting it would break that CLI tooling. Kept, documented as a real but lower-risk duplication (a contract-validation tool that validates against a registry the API doesn't actually use). |
| `packages/mi_game_core/lib/src/contracts/mi_game_result.dart` (Dart, live) vs. `apps/api/schemas/progress.py` `SaveGameResultRequest` (Python, live) | These are the two contracts actually used by real code (game screens and the new `/games/{id}/result` endpoint, respectively). They are field-for-field aligned (checked manually) and the Python schema's docstring says so explicitly. They remain two hand-maintained mirrors rather than one generated source of truth — a real "no single source of truth" gap, but converting to codegen (e.g. OpenAPI → Dart) is a tooling investment outside this session's scope. Flagged in `NEXT_PHASE_PLAN.md`. |
| `packages/mi_game_core` / `packages/mi_game_ui` / `packages/mi_game_content` / `packages/mi_game_audio` / `packages/mi_game_progress` / `packages/mi_game_accessibility` / `packages/mi_game_testing` vs. `packages/game_sdk` | Different layers, not duplicates: `mi_game_*` is the client-side game engine/UI framework used directly by game screens; `game_sdk` is a separate network/DTO layer (`GameLaunchRequest`, `GameResult`, `GameSnapshot`, `GameClient`) consumed only by `packages/api_client`. Overlapping *names* (`GameResult` vs `MiGameResult`) but distinct code paths — worth eventually consolidating but not a same-purpose duplicate pair. |
| `adaptive_core`, `mastery_core`, `recommendation_core`, `spaced_repetition`, `learning_core`, `learning_analytics` | Checked class names across all six — no overlapping responsibilities. Legitimately distinct (hints/state, mastery scoring, session recommendation, SM-2 scheduling, lesson/content engine, parent analytics). Not duplicates; the real issue is they're unwired to `apps/mobile` (see `PRODUCTION_BLOCKERS.md`), not that they duplicate each other. |
| `apps/mobile/lib/src/games/math_race/math_race_screen.dart`, `math_supermarket_screen.dart` | **Genuinely dead** — superseded by `ChoiceGameScreen` (which `main.dart` actually uses for both math_race and math_supermarket), referenced nowhere, and **do not even compile** (`flutter analyze` reports undefined `GameScaffold`/`QuestionCard`/`AnswerButton`/`AnimatedFeedback` and a missing-required-argument error). A destructive-action safety check in this session's tooling declined to delete these files because they weren't named in the pre-approved plan; recommend deleting them in a follow-up with explicit sign-off. |
| `apps/mobile/lib/screens/game_screen.dart` (`GameScreen`, at GoRouter's `/game/:gameId`) | A hardcoded demo (fixed score/star increments, no real questions) — not visually a duplicate of the real per-game screens (`MemoryCardsScreen` etc.), but functionally redundant with them once the entry-point split (see `PRODUCTION_BLOCKERS.md`) is resolved. This session made its completion path call the *real* `/games/{id}/result` endpoint (with offline-queue fallback) rather than rewriting or deleting it, since replacing it requires the larger entry-point merge that was out of scope. |
| `apps/mobile/lib/main.dart`'s `MiAcademyApp`/`HomeScreen` vs. `apps/mobile/lib/app.dart`'s `MiAcademyApp` | **Two same-named classes, two different app shells** — the single most significant duplication found this session. See `PRODUCTION_BLOCKERS.md` for details and recommendation; not resolved this session because merging them safely (migrating the working multi-game asset-loading logic, updating/removing the two widget tests that currently cover the `main.dart` shell) is a larger, higher-risk change than this session's fixes. |

## Contracts not unified this session

`GameLaunchRequest`/`GameResult`/`Snapshot`/`Child`/`Parent`/`Lesson`/`Skill`/`Progress` each have 2-4 independent hand-written definitions spread across `apps/api/schemas/*.py`, `apps/api/models/__init__.py`, `packages/content_sdk`, `packages/*_core`. Only the `MiGameResult`/`SaveGameResultRequest` pair was verified field-for-field this session (because it's the one that got wired end-to-end). The rest were not diffed field-by-field — flagged as a real gap in `PRODUCTION_BLOCKERS.md`.
