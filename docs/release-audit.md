# MI Academy 1.0 — Release Audit

Date: 2026-07-18
Branch: `fix/internal-beta-hardening` (HEAD at time of writing: `9e0fb34`)
Scope: Direct verification against this working tree, its test suite, and
live CI runs on this branch. Nothing here is carried over from prior
session summaries without re-verification — every finding below cites the
exact command run and its actual output.

## Executive summary

The mobile app's six MVP games, offline persistence, parent PIN gate, and
backend API are functionally real (not stubbed) and the canonical test
suite is green: `flutter analyze` (0 issues), `flutter test` (86 passed, 6
explicitly-skipped platform-limited golden tests, 0 failed), and `pytest`
(159 passed). Android release artifacts (APK + AAB) build successfully
unsigned in this environment; iOS requires macOS tooling not available here
and is verified via CI's `ios-build` job instead.

Two Critical findings from the previous audit pass (fake dark theme,
hardcoded Vietnamese game content) are now fixed and verified. This pass
also surfaced a **new, larger Critical finding**: most on-screen UI text
(button labels, headers, tutorial copy, feedback messages — as opposed to
game *content*, which is now locale-aware) is still hardcoded Vietnamese
string literals with no localization plumbing, even though a translated
`.arb` key set already exists and is unused. First-launch locale selection
is now implemented. See the findings table for full detail and honest
status on every item the audit was asked to cover.

### Items the audit explicitly asked to be recorded, with status

- **Fake dark-theme configuration** — see RA-01. **Fixed.**
- **Hardcoded Vietnamese locale through game content/session flow** — see RA-02/RA-03. **Fixed** for game content and the app shell. See RA-05 for the still-open UI-chrome gap — do not read RA-02–04 as "localization is done."
- **First-time locale selection missing** — see RA-04. **Fixed.**
- **Six nondeterministic/environment-sensitive golden failures** — see RA-06. **Fixed**; canonical suite (`flutter test` locally, `mobile-test-build` on CI) is green with 0 failures.
- **Five-profile limit verification** — real and server-enforced; untested boundary, see RA-08.
- **Translation-key parity** — currently matches (57/57); no CI enforcement, see RA-09.
- **Hardcoded user-facing string sweep** — see RA-05. **Open, largest remaining item.**
- **TODO/FIXME/mock/stub sweep** — `grep -rn "TODO\|FIXME\|XXX" apps/mobile/lib apps/api --include=*.dart --include=*.py` → 0 matches. `mock`/`stub` matches are only in code comments about testability, not real functionality replaced by mocks. **Clean.**
- **Parent PIN route protection** — enforced via `router.dart`'s `redirect` guard on `/parent` and `/parent/settings`; covered by `test/parent_route_guard_test.dart` (2/2 passing, part of the 86-test `flutter test` total). **Verified.**
- **Local offline startup** — `SplashScreen._resolveStartRoute` degrades to `/login` on any auth-restore error (storage failure, API unavailable), confirmed by existing splash-routing tests plus this pass's addition of the `localeConfirmed` gate ahead of it. **Verified.**
- **Settings persistence** — `test/widget_test.dart`: "Parent settings persist after reopening the screen" passing; this pass added `localeConfirmed`/language persistence tests in `test/locale_selection_test.dart` (8/8 passing). **Verified.**
- **All six game completion paths** — `python tools/level_validator/solve_levels.py` confirms 10/10 levels solvable per game for all six games; `flutter test` includes a full playthrough/completion assertion per game in `widget_test.dart` and `game_slice_golden_test.dart`. **Verified.**
- **Backend formatting, linting, typing, tests, migrations** — tests pass (159/159); formatting/linting/typing are unconfigured tooling with real findings recorded honestly in RA-11/RA-12/RA-13 rather than glossed over; migrations validated via the `postgres-integration` CI job (Alembic against real Postgres) — see command battery below; a local SQLite `alembic upgrade head` attempt fails as expected (`NotImplementedError: No support for ALTER of constraints in SQLite dialect`), which is why that CI job exists and is the real verification path.
- **Release-build status (APK, AAB, unsigned iOS)** — see command battery below. APK and AAB both built successfully in this environment; iOS requires macOS tooling not present here, verified via CI's `ios-build` job instead.
